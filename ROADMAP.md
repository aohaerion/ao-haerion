# AO Haerion Roadmap

This roadmap describes the early public direction of AO Haerion.

It is intentionally small and conservative.

AO Haerion starts with documentation, concepts, and milestone design before any broader system claims are made.

## Current status

**AO HAERION PUBLIC FOUNDATION — PUBLIC DOCUMENTATION DRAFT — NON BASELINE**

This roadmap is not a baseline.
It is a public working direction.

## Roadmap sequence

### M001 — Governed Memory Layer

**Status:** Proposed public design milestone  
**Focus:** Preserve context, decisions, evidence, and direction across interrupted work.

M001 is the first technical design milestone because AO Haerion needs a safe way to resume complex work without pretending that memory is complete, perfect, or automatically reliable.

M001 does not define a full runtime system.
It defines the public design frame for governed memory.

See: [docs/m001-governed-memory-layer.md](docs/m001-governed-memory-layer.md)

### M002 — Future exploration

**Status:** Future exploration  
**Focus:** To be defined after M001 becomes clearer.

Possible future work may explore how clarified memory supports structured decisions, goals, or project continuation.

No detailed scope is declared yet.

### M003 and later — Future exploration

**Status:** Future exploration  
**Focus:** Not defined.

Later milestones should be introduced only when the previous layer is understandable, documented, and limited clearly enough.

## Roadmap principles

AO Haerion should grow in small public steps.

Each milestone should state:

- what it tries to solve;
- what it does not solve;
- what evidence or documentation it produces;
- what risks or limits remain;
- what should not be claimed yet.

## What this roadmap does not claim

This roadmap does not claim that AO Haerion is:

- complete;
- validated;
- production-ready;
- a runtime system;
- a full autonomous agent framework;
- a replacement for human judgment.
