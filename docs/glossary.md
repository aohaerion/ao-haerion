# AO Haerion Glossary

This glossary defines early public terms used by AO Haerion.

The definitions are intentionally practical and limited.

## Context

The surrounding information needed to understand a situation, decision, goal, or path of work.

Context may include:

- current state;
- constraints;
- previous decisions;
- open questions;
- relevant evidence.

## Memory

Stored information that can help continue or understand work later.

In AO Haerion, memory should not be treated as automatically complete or automatically correct.

## Governed memory

Memory that is structured, limited, traceable, and explicit about its status.

Governed memory should make clear:

- what is preserved;
- what is not preserved;
- what is known;
- what is uncertain;
- what has evidence;
- what should not be claimed.

## Decision

A selected direction among possible options.

A useful decision should preserve:

- what was chosen;
- why it was chosen;
- what evidence or assumptions supported it;
- what remains uncertain.

## Evidence

Material used to support a statement, decision, or state.

Evidence may include:

- documents;
- repository files;
- notes;
- logs;
- cited sources;
- explicit user-provided inputs.

Evidence does not automatically make a statement true.
It makes the basis of the statement visible.

## Direction

The active path or intended next movement of work.

Direction is not the same as completion.
It describes where the work is currently pointing.

## Resume path

To continue interrupted work using preserved context, decisions, evidence, and direction.

A good resume path should reduce confusion without pretending that nothing was lost.

## Overclaim

A statement that presents something as more complete, proven, validated, or operational than it really is.

Examples of overclaim include:

- calling a draft a baseline;
- presenting a design as a working runtime;
- describing a partial milestone as a complete system;
- implying validation that has not happened.
